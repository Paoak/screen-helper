# Screen Helper

Локальный нейро-ассистент для скриншотов. Нажимаете горячую клавишу, программа снимает экран (или выделенную область), отправляет снимок в **vision-модель, запущенную у вас в [Ollama](https://ollama.com)**, и показывает ответ в небольшом окне **поверх всех окон**, не забирая фокус у браузера. Всё работает локально: ни облака, ни аккаунтов, ни API-ключей.

Типичный сценарий: на экране вопрос с вариантами ответа (учебный тест, тренажёр, опросник), вы жмёте **Ctrl+Alt+A**, обводите вопрос и через несколько секунд видите ответ с коротким объяснением. Но подойдёт и для любого другого вопроса «по картинке»: ошибка в окне, график, фрагмент кода.

## Как это работает

```
 хоткей (Ctrl+Alt+S / Ctrl+Alt+A)
        │
        ▼
 скриншот (в памяти, на диск не пишется)  ──►  [только область: затемнённый снимок, выделяете мышкой]
        │
        ▼
 уменьшение до max_side px + JPEG + base64
        │
        ▼
 POST http://localhost:11434/api/chat  (Ollama, потоковый ответ, ваша модель)
        │
        ▼
 окно-оверлей справа вверху: «Думаю…» → ответ появляется по мере генерации
```

Что важно знать про устройство:

- **Каждый снимок - отдельный запрос без истории.** Модель не помнит предыдущие скриншоты, поэтому контекст не растёт, и 15 запросов подряд ничем не отличаются от первого.
- **Новый снимок отменяет предыдущий запрос.** Если вы нажали хоткей, пока модель ещё отвечала, старый запрос обрывается, а не стоит в очереди Ollama.
- **Окно ответа прячется на время снимка**, чтобы не попасть в кадр, и не забирает фокус (флаг `WS_EX_NOACTIVATE` на Windows).
- **Рассуждение модели не показывается**, вместо него в окне счётчик «Думаю… (N симв. рассуждения)», чтобы было видно, что процесс идёт.

## На чём проверено

Программа разрабатывалась и вручную проверялась (хоткеи, выбор области, оверлей, режим рассуждения) на:

| | |
|---|---|
| ОС | Windows, запуск из PyCharm |
| Видеокарта | AMD Radeon RX 7800 XT, 16 ГБ VRAM |
| Модель | `gemma4:12b` (11.9B параметров, квантизация Q4_K_M; в `ollama show` у неё capabilities: completion, vision, audio, tools, thinking) |
| Ollama | версия, подходящая для `gemma4` (в `ollama show` у модели указано `requires 0.30.9`) |

Юнит-тесты логики (без GUI) выполнялись на Linux, Python 3.13; в GitHub Actions они запускаются на Python 3.10-3.13 (`.github/workflows/tests.yml`).

**Чего проверено не было:** macOS, Linux как рабочая ОС (библиотека `keyboard` там требует root или не поддерживается), NVIDIA-карты, несколько мониторов, другие модели. Вероятно, часть из этого заработает, но заявлять этого нельзя.

Качество ответов зависит от модели, а не от программы. Бенчмарков точности здесь нет, цифр «правильных ответов в процентах» тоже.

## Ответственное использование

Программа - инструмент для самопроверки, тренировки и работы со своими материалами. Прежде чем применять её к чему-либо оцениваемому (экзамен, зачёт, отбор, сертификация), проверьте правила: во многих таких случаях помощь посторонних инструментов запрещена, а нарушение может привести к дисквалификации или отчислению. Ответственность за использование лежит на вас.

Модель может ошибаться, причём уверенно. Не полагайтесь на её ответ там, где цена ошибки высока, и проверяйте по документации.

## Установка и первый запуск

### 1. Ollama и модель

1. Установите Ollama: <https://ollama.com/download>.
2. Скачайте vision-модель. Пример для проверенной конфигурации:
   ```powershell
   ollama pull gemma4:12b
   ```
3. **Проверьте, что у модели есть `vision`**, иначе картинку она не увидит:
   ```powershell
   ollama show gemma4:12b
   ```
   В блоке `Capabilities` должно быть слово `vision`. Слово `thinking` означает, что модель умеет рассуждать (см. [режим рассуждения](#режим-рассуждения-think)).
4. Прогрейте модель (первый запуск грузит её в видеопамять и идёт заметно дольше):
   ```powershell
   ollama run gemma4:12b "привет"
   ```
5. Убедитесь, что модель на видеокарте, а не на процессоре:
   ```powershell
   ollama ps
   ```
   В колонке `PROCESSOR` должно быть `100% GPU`. Если там указан CPU, всё будет в разы медленнее: проверьте драйверы видеокарты.

### 2. Программа

Нужен Python 3.10 или новее (с `tkinter`: на Windows он входит в стандартный установщик с опцией *tcl/tk and IDLE*).

```powershell
git clone <URL-репозитория>
cd screen-helper
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python main.py
```

Если PowerShell не даёт активировать окружение, выполните один раз `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.

В консоли появится строка со списком горячих клавиш и используемой моделью. Окно консоли можно свернуть, но не закрывать.

### Запуск из PyCharm

1. Откройте папку как проект, интерпретатором выберите `.venv` проекта.
2. Установите зависимости в **это** окружение (терминал PyCharm, `Alt+F12`): `pip install -r requirements.txt`.
3. Запустите `main.py` кнопкой Run. Остановить можно красным квадратом или хоткеем **Ctrl+Alt+Q**.

> Хоткей **Ctrl+Alt+S** глобальный и срабатывает в том числе в PyCharm, где он открывает настройки. Если мешает, поменяйте его в `config.json` (см. [Настройка](#настройка)).

## Использование

| Хоткей | Действие |
|---|---|
| **Ctrl+Alt+S** | снимок всего основного экрана |
| **Ctrl+Alt+A** | снимок выделенной области: тянете рамку левой кнопкой мыши; **Esc** или правая кнопка - отмена |
| **Ctrl+Alt+H** | скрыть / показать окно с ответом |
| **Ctrl+Alt+Q** | выйти из программы |

Рекомендации:

- **Используйте выделение области (Ctrl+Alt+A).** Чем меньше лишнего на картинке и крупнее текст, тем точнее модель читает вопрос, и тем быстрее ответ.
- Захватывайте **вопрос вместе со всеми вариантами ответа**. Если вариант не попал в кадр, модель его не видит.
- Не отправляйте следующий снимок, пока не получили ответ: предыдущий запрос будет отменён, и его ответ вы не увидите.
- Первый запрос после запуска или после долгого простоя медленнее остальных: модель загружается в память (`keep_alive` держит её там заданное время).

## Настройка

Все настройки необязательны. Чтобы что-то изменить, скопируйте пример и оставьте в нём только нужные поля:

```powershell
Copy-Item config.example.json config.json
```

Программа читает `config.json` из **текущей папки** при запуске. Другой файл можно указать явно:

```powershell
python main.py --config examples\config.fast.json
```

`config.json` добавлен в `.gitignore`, чтобы ваши личные промпты и настройки случайно не попали в репозиторий. Поля, имена которых начинаются с `_` (например `_comment`), игнорируются, так что в JSON можно оставлять пометки.

| Поле | По умолчанию | Описание |
|---|---|---|
| `ollama_url` | `http://localhost:11434/api/chat` | Адрес Ollama. Другой порт или другая машина в сети: меняйте здесь (см. [приватность](#приватность-и-безопасность)) |
| `model` | `gemma4:12b` | Имя модели, как в `ollama list`. Нужна поддержка изображений |
| `keep_alive` | `"30m"` | Сколько держать модель в памяти после запроса |
| `num_ctx` | `16384` | Размер контекста. Для одного скриншота без рассуждения хватает 8192; **с рассуждением ставьте не меньше 16384** |
| `max_side` | `1600` | Максимальная сторона скриншота в пикселях. Меньше: быстрее, но мелкий текст читается хуже |
| `think` | `true` | `true`, `false` или уровень `"low"`, `"medium"`, `"high"` ([подробнее](#режим-рассуждения-think)) |
| `request_timeout` | `300` | Сколько секунд ждать очередную порцию данных от Ollama |
| `hotkey_full` | `ctrl+alt+s` | Хоткей снимка экрана |
| `hotkey_area` | `ctrl+alt+a` | Хоткей снимка области |
| `hotkey_hide` | `ctrl+alt+h` | Хоткей скрытия окна ответа |
| `hotkey_quit` | `ctrl+alt+q` | Хоткей выхода |
| `prompt` | см. `config.py` | Инструкция для модели ([как писать](#как-писать-и-менять-промпт)) |

Хоткеи задаются в формате библиотеки [`keyboard`](https://github.com/boppreh/keyboard), например `ctrl+shift+f9`.

Ошибки в файле (неверный JSON, неизвестное поле, неподходящий тип значения) программа сообщает понятным текстом и завершается с кодом 2, не запуская GUI.

Готовые примеры лежат в [`examples/`](examples):

| Файл | Для чего |
|---|---|
| `config.api-questions.json` | тематический промпт (вопросы про API), рассуждение включено |
| `config.fast.json` | быстрый режим: без рассуждения, ответ одной строкой, меньше контекст и размер снимка |
| `config.other-model.json` | пример смены модели |

## Как писать и менять промпт

Промпт - это текст, который отправляется модели вместе со скриншотом. Он сильнее всего влияет на формат и качество ответа. Хорошо работает такая структура:

1. **Что на картинке:** «На скриншоте вопрос с вариантами ответа».
2. **Тематика** (если она известна заранее): «Вопросы про API: пагинация, фильтрация, асинхронные операции». Это помогает модели выбрать правильную терминологию и отсечь неподходящие толкования.
3. **Формат ответа:** «Сначала одной строкой правильный вариант (буква и текст), затем 1-2 предложения объяснения».
4. **Поведение при неуверенности:** «Если текст нечитаем или вопрос обрезан - так и скажи, ничего не выдумывай». Без этой фразы модель склонна уверенно додумывать то, чего не видит.
5. **Язык:** «Отвечай на языке вопроса».

Практические советы:

- **Не просите «только букву», если хотите проверять ответ.** Короткое объяснение позволяет заметить, что модель поняла вопрос неправильно. Для простых вопросов «только вариант» допустимо и быстрее (см. `examples/config.fast.json`).
- Режим рассуждения повышает точность за счёт самого рассуждения, а не за счёт «подробных объяснений» в ответе. Просить объяснять шаг за шагом при включённом `think` обычно незачем.
- Для вопросов с несколькими правильными ответами укажите это явно: «Если правильных вариантов несколько, перечисли все».
- Для открытых вопросов уточняйте длину: «ответ в 2-3 предложениях».
- Меняйте промпт в `config.json`, а не в коде, и проверяйте на нескольких разных вопросах, а не на одном.
- Слишком длинный промпт с множеством правил может ухудшить результат у небольших моделей. Начинайте с короткого.

Пример промпта для узкой темы лежит в `examples/config.api-questions.json`.

## Режим рассуждения (think)

Часть современных моделей умеет **рассуждать перед ответом**: сначала генерирует цепочку рассуждений, и только потом итоговый ответ. Ollama отдаёт рассуждение отдельным полем (`message.thinking`), а ответ - отдельно (`message.content`). Программа **не показывает** рассуждение, только счётчик символов, пока оно идёт.

Включение: `"think": true` в `config.json`. Программа **всегда отправляет параметр `think` явно**, поэтому значение по умолчанию, зашитое в самой модели, не влияет на её поведение здесь.

**Когда включать:** вопросы с логикой, расчётами, подвохами, несколькими «похожими» вариантами, вопросы по сложной терминологии. Точность обычно заметно выше.

**Когда выключать (`"think": false`):** простые фактические вопросы, когда важна скорость. С рассуждением ответ может идти от десятков секунд до нескольких минут (зависит от модели, видеокарты и вопроса), без него - обычно за несколько секунд.

**Цена рассуждения:**

- *Время.* Рассуждение - это тоже сгенерированные токены.
- *Контекст.* Рассуждение занимает место в `num_ctx`. Если контекста не хватает, модель может так и не дойти до ответа. Программа в этом случае покажет сообщение «Модель закончила, но не вернула ответ…»: увеличьте `num_ctx` или выключите `think`.
- *Память.* Больший `num_ctx` увеличивает расход видеопамяти. После изменения проверяйте `ollama ps`: модель должна остаться на `100% GPU`.

### Модели, у которых режима рассуждения может не быть

Не все модели поддерживают `think`. Проверить можно в `ollama show <модель>`: в `Capabilities` должно быть `thinking`.

Что делает программа, если `think` включён, а модель его не поддерживает: Ollama отвечает ошибкой HTTP 400 с упоминанием thinking. Программа показывает уведомление «Эта модель не поддерживает режим рассуждения - отвечаю без него…» и **автоматически повторяет запрос без `think`**. Ответ вы получите, но каждый запрос будет начинаться с неудачной попытки. Поэтому для таких моделей лучше сразу поставить `"think": false`.

Другие нюансы, зависящие от модели (смотрите карточку модели на [ollama.com/library](https://ollama.com/library) и документацию Ollama):

- Некоторые модели принимают вместо `true`/`false` **уровень рассуждения** (`"low"`, `"medium"`, `"high"`). Программа пропускает такие значения как есть.
- У некоторых моделей рассуждение нельзя отключить полностью, а у некоторых бывают отдельные «thinking»- и «instruct»-сборки с разными тегами.
- Для рассуждающих моделей Ollama должна быть достаточно свежей: на старых версиях параметра `think` может не быть, и запрос завершится ошибкой.

## Выбор модели

Подходит любая модель из Ollama **с capability `vision`**. Ниже не рейтинг, а отправные точки для сравнения на ваших вопросах: списки моделей быстро меняются, актуальные смотрите на [ollama.com/library](https://ollama.com/library).

| Модель | Комментарий |
|---|---|
| `gemma4:12b` | Проверенная конфигурация: на 16 ГБ видеопамяти помещается целиком, поддерживает vision и thinking |
| `qwen3-vl:8b` | Компактная (порядка 6 ГБ), сильна в распознавании текста на скриншотах; стоит сравнить, особенно если вопросы не на английском |
| `qwen3-vl:30b` | MoE-модель: на 16 ГБ часть слоёв уйдёт в оперативную память, зато активна лишь малая часть параметров, поэтому замедление может быть терпимым. Скорость нужно мерить самому |
| Модели крупнее 20-30B (плотные) | На 16 ГБ видеопамяти уходят в RAM и работают медленно; для сценария «нажал клавишу, получил ответ» обычно неудобны |

Как выбирать:

1. Смотрите, чтобы **модель + контекст помещались в видеопамять**. Грубая оценка для квантизации Q4: 0.55-0.65 ГБ на миллиард параметров, плюс vision-проектор и KV-кэш, который растёт вместе с `num_ctx`.
2. После первого запроса проверяйте `ollama ps`. `100% GPU` - хорошо. Что-то вроде `30%/70% CPU/GPU` - модель не поместилась, и скорость упадёт.
3. Сравнивайте модели **на одних и тех же скриншотах**: смените `model` в `config.json` и отправьте тот же вопрос. Это надёжнее любого обзора.
4. Если ответ плохой на мелком тексте, сначала попробуйте выделить область и поднять `max_side`, а не менять модель.

## Краевые случаи и устранение неполадок

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| Хоткеи ничего не делают, в консоли нет строки `hotkey: …` | Библиотека `keyboard` не получает нажатия | Запустите программу (или PyCharm) **от имени администратора**. Проверьте, не занята ли комбинация другой программой (скриншотеры, мессенджеры иногда используют Ctrl+Alt+A). Смените хоткей в `config.json` |
| Строка `hotkey: …` есть, а окна нет | Ошибка при захвате или запросе | Смотрите консоль: после `hotkey:` должны идти `capture:` и `request #N:`, на каком шаге оборвалось - там и причина. Если есть трассировка - пришлите её в Issue |
| Хоткей срабатывает не только у программы (например, открывает настройки PyCharm) | Хоткей глобальный | Смените комбинацию в `config.json` |
| Экран затемнён, курсор-«крестик» | Открыт слой выбора области | **Esc** или правая кнопка мыши. Если не помогло: **Ctrl+Alt+Q** или завершите `python.exe` в диспетчере задач |
| Две копии программы, всё ведёт себя странно | Две копии одновременно ловят хоткеи | Закройте лишнюю (в PyCharm: красный квадрат у старого запуска, либо диспетчер задач) |
| «Думаю…» очень долго | Включено рассуждение; модель только загружается; модель не на GPU | Смотрите счётчик символов: растёт - модель работает. Проверьте `ollama ps`. Для простых вопросов поставьте `"think": false` |
| «Модель закончила, но не вернула ответ» | Рассуждение исчерпало контекст | Увеличьте `num_ctx` или выключите `think` |
| «Не удаётся подключиться к Ollama» | Ollama не запущена или другой адрес/порт | Запустите Ollama, проверьте `ollama list`, при необходимости поправьте `ollama_url` |
| «Модель … не найдена» | Модель не скачана или имя не совпадает | `ollama pull <имя>`; сверьте `model` с `ollama list` |
| «Не хватает памяти…» или всё очень медленно | Модель или контекст не помещаются в память | Уменьшите `num_ctx`, выберите модель поменьше, закройте другие программы на GPU; смотрите `ollama ps` |
| «Ollama не отвечает больше N с» | Таймаут | Увеличьте `request_timeout`; для рассуждающих моделей на сложных вопросах это нормально |
| Ответ не относится к скриншоту / игнорирует картинку | У модели нет `vision` | `ollama show <модель>`: нужен `vision` в `Capabilities` |
| Модель путает буквы вариантов, не видит часть текста | Мелкий текст, слишком сильное сжатие, вопрос обрезан | Выделяйте область, увеличьте масштаб страницы в браузере (Ctrl+колесо), поднимите `max_side`, убедитесь, что все варианты в кадре |
| Вопрос не помещается на экране (нужна прокрутка) | Снимок захватывает только видимое | Уменьшите масштаб страницы, чтобы всё влезло. Раздельные снимки не помогут: запросы независимы, и модель не видит предыдущий |
| Снимок чёрный | Защищённое содержимое (DRM), аппаратное ускорение некоторых окон | Отключите аппаратное ускорение в приложении/браузере, если это возможно |
| Тест на втором мониторе | Снимается только основной монитор | Перетащите окно с вопросом на основной монитор |
| Рамка выделения смещена, снимок «не в том месте» | Нестандартный масштаб Windows (125/150%), несколько мониторов с разным DPI | Программа включает DPI-режим сама; если смещение есть, опишите в Issue конфигурацию мониторов |
| Ответ на другом языке | Промпт не указывает язык | Добавьте «Отвечай на языке вопроса» (или конкретный язык) |
| Ответ уверенный, но неверный | Любая модель ошибается; особенно по узким темам и версиям библиотек/API | Включите `think`, выделите область, сравните с другой моделью, проверьте по документации |
| Первый запрос после простоя долгий | Модель выгружена из памяти | Увеличьте `keep_alive`, например `"2h"` |
| Антивирус ругается на программу | Глобальный перехват клавиш выглядит подозрительно для эвристик | Код открыт (см. [приватность](#приватность-и-безопасность)); при необходимости добавьте папку в исключения |
| `Ошибка настроек: …` при запуске | Неверный `config.json` | Текст ошибки указывает поле; сверьтесь с таблицей настроек. Файл с BOM (из Блокнота) принимается |

## Приватность и безопасность

- **Всё локально.** По умолчанию снимок уходит только на `localhost:11434`, то есть в вашу Ollama. Если вы укажете в `ollama_url` другую машину, снимки экрана будут отправляться на неё. Делайте это осознанно.
- **Снимки не сохраняются на диск.** Они живут в памяти, кодируются в JPEG и передаются в запросе.
- **Хоткеи.** Библиотека `keyboard` ставит глобальный перехватчик клавиатуры; для этого она и нужна. Код только регистрирует четыре комбинации через `add_hotkey` и **не записывает и не логирует нажатия**, в консоль печатается лишь строка `hotkey: экран/область`. Убедиться можно, прочитав `screen_helper/app.py`: он короткий.
- **Экран может содержать чужое:** почту, мессенджеры, пароли. Используйте выделение области, чтобы в кадр попадало только нужное.
- Не запускайте программу от администратора без необходимости, и только из источника, которому доверяете.

## Разработка и тесты

Структура проекта:

```
screen-helper/
├── main.py                    # точка входа для PyCharm / python main.py
├── screen_helper/
│   ├── config.py              # настройки, загрузка и проверка config.json
│   ├── core.py                # логика без GUI: запрос к Ollama, разбор потока, состояние окна, защита хоткеев
│   ├── ui.py                  # tkinter: окно ответа и выбор области
│   ├── app.py                 # хоткеи, очередь событий, захват экрана
│   └── __main__.py            # python -m screen_helper
├── tests/                     # pytest
├── examples/                  # примеры config.json
├── config.example.json        # все настройки с значениями по умолчанию
└── requirements*.txt
```

Логика намеренно отделена от GUI: всё, что можно проверить без экрана и без Ollama, находится в `config.py` и `core.py`.

Запуск тестов:

```powershell
pip install -r requirements-dev.txt
pytest
```

**Что покрыто тестами** (на момент публикации - 94 теста): загрузка и проверка настроек (BOM, неизвестные поля, неверные типы, актуальность файлов-примеров); подготовка картинки (уменьшение без растягивания, разные цветовые режимы, оригинал не меняется); сборка запроса; разбор потока Ollama (рассуждение, ответ, мусорные строки, ошибки в потоке); `ask_model` с подменённым сетевым вызовом (успех, отмена устаревшего запроса, 404 модели, нехватка памяти, обрыв соединения, таймаут, автоматический повтор без `think`); перевод выделения мышкой в рамку (DPI-масштаб, выход за края экрана, случайные клики); состояние окна ответа (устаревшие события, ошибка посреди ответа, пустой ответ); защита от дублей хоткея.

**Что тестами не покрыто:** `ui.py` и `app.py` (tkinter, глобальные хоткеи, реальный захват экрана, окно без фокуса). Для них нужен рабочий стол Windows, поэтому они проверяются вручную. Реальные ответы модели тоже не тестируются: тесты не вызывают Ollama.

## Ограничения и идеи

Известные ограничения: проверено только на Windows; снимается только основной монитор; нет истории запросов; позицию и размер окна ответа можно поменять только в коде (`Overlay` в `ui.py`).

Идеи для развития:

- снимок всех мониторов (`ImageGrab.grab(all_screens=True)` в Pillow на Windows);
- хоткей, который переключает `think` без перезапуска;
- копирование ответа в буфер обмена;
- перетаскиваемое и изменяемое по размеру окно ответа;
- переключение между несколькими моделями «на лету» для сравнения.
