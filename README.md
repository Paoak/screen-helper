# Screen Helper

Локальный нейро-ассистент для скриншотов. Нажимаете горячую клавишу, программа снимает экран (или выделенную область), отправляет снимок в **vision-модель, запущенную у вас на компьютере**, и показывает ответ в небольшом окне **поверх всех окон**, не забирая фокус у браузера. Всё работает локально: ни облака, ни аккаунтов, ни API-ключей.

Поддерживаются два способа запустить модель:

| Бэкенд | Что это | Для чего в этом проекте |
|---|---|---|
| `ollama` (по умолчанию) | [Ollama](https://ollama.com) и её модели | Самый простой путь. Проект начинался с `gemma4:12b` |
| `openai` | Любой OpenAI-совместимый сервер, например `llama-server` из llama.cpp | Для моделей, которых нет в Ollama. Проверено на **Ternary Bonsai 2.5 27B** |

Типичный сценарий: на экране вопрос с вариантами ответа (учебный тест, тренажёр, опросник), вы жмёте **Ctrl+Alt+A**, обводите вопрос и через несколько секунд видите ответ с коротким объяснением. Но подойдёт и для любого другого вопроса «по картинке»: ошибка в окне, график, фрагмент кода.

## С чего всё началось

Идея простая: во время онлайн-теста не хочется уходить из вкладки браузера и копировать вопрос в чат. Поэтому программа ловит глобальный хоткей, сама делает снимок и показывает ответ в маленьком окне поверх всего.

1. **Ollama + `gemma4:12b`.** Первая версия работала с Gemma 4 12B через Ollama. Эта модель помещается целиком в 16 ГБ видеопамяти AMD RX 7800 XT, умеет читать картинки (`vision`) и рассуждать (`thinking`). Этот вариант остался в проекте и остаётся основным для простого старта.
2. **Статья на Хабре.** Потом вышла статья [«Ternary Bonsai 2.5 27B»](https://habr.com/ru/articles/1112562/): модель на 27 млрд параметров от PrismML (по данным статьи, основана на Qwen3.8 27B, лицензия Apache 2.0), веса которой сжаты до **5,93 ГБ** против 53,8 ГБ в FP16 (тернарное квантование, 1,76 бита на вес). Для 16 ГБ видеопамяти это интересно: модель втрое крупнее Gemma 12B помещается в карту и оставляет место под контекст и скриншоты. Насколько она точнее Gemma на ваших вопросах, нужно проверять самому: здесь это не измерялось. Статья и подтолкнула попробовать это семейство.
3. **Что получилось.** Модель запускается через форк llama.cpp от PrismML, а не через Ollama, поэтому в программу добавлен второй бэкенд, `openai`. На RX 7800 XT сервер по логу выдаёт порядка **47 токенов/с на генерацию** и около **430 токенов/с на обработку запроса** со скриншотом (подробности и оговорки в разделе [«На чём проверено»](#на-чём-проверено)), так что по ощущениям автора ответы приходят достаточно быстро даже с рассуждением.

Статья сама предупреждает, что бенчмарки в ней приведены разработчиком и независимо не воспроизведены. Здесь точность модели тоже **не измерялась**: проверялось, что связка работает и отвечает быстро.

## Как это работает

```
 хоткей (Ctrl+Alt+S / Ctrl+Alt+A)
        │
        ▼
 скриншот (в памяти, на диск не пишется)  ──►  [только область: затемнённый снимок, выделяете мышкой]
        │
        ▼
 уменьшение до max_side px + JPEG + base64
        │
        ├── backend = "ollama":  POST http://localhost:11434/api/chat          (поток JSON-строк)
        └── backend = "openai":  POST http://localhost:8080/v1/chat/completions (поток SSE)
        │
        ▼
 окно-оверлей справа вверху: «Думаю…» → ответ появляется по мере генерации
```

Что важно знать про устройство:

- **Каждый снимок - отдельный запрос без истории.** Модель не помнит предыдущие скриншоты, поэтому контекст не растёт, и 15 запросов подряд ничем не отличаются от первого.
- **Новый снимок отменяет предыдущий запрос.** Если вы нажали хоткей, пока модель ещё отвечала, старый запрос обрывается, а не стоит в очереди сервера.
- **Окно ответа прячется на время снимка**, чтобы не попасть в кадр, и не забирает фокус (флаг `WS_EX_NOACTIVATE` на Windows).
- **Рассуждение модели не показывается**, вместо него в окне счётчик «Думаю… (N симв. рассуждения)», чтобы было видно, что процесс идёт.
- **Бэкенды взаимозаменяемы для окна ответа:** оно получает одни и те же события («думает», «кусок ответа», «ошибка», «готово»), откуда бы они ни пришли.

## На чём проверено

Программа разрабатывалась и вручную проверялась (хоткеи, выбор области, оверлей, режим рассуждения) на:

| | |
|---|---|
| ОС | Windows, запуск из PyCharm и из `.bat`-файлов |
| Видеокарта | AMD Radeon RX 7800 XT, 16 ГБ VRAM |
| Ollama-вариант | `gemma4:12b` (11.9B параметров, квантизация Q4_K_M; в `ollama show`: completion, vision, audio, tools, thinking; нужна Ollama версии 0.30.9 или новее: так указано в `ollama show`, строка `requires 0.30.9`) |
| llama.cpp-вариант | **Ternary Bonsai 2.5 27B**, веса `Ternary-Bonsai-2.5-27B-PQ2_0-mtp.gguf` (7,49 ГБ) + проектор `Ternary-Bonsai-2.5-27B-mmproj-Q8_0.gguf` (0,63 ГБ); сервер - форк PrismML (`llama-prism-b12178`, сборка **Vulkan**), запущен скриптом из [Bonsai-demo](https://github.com/PrismML-Eng/Bonsai-demo) с `-ngl 99`; контекст 16384, а при высоком уровне рассуждения 32768 |

**Замеры скорости** взяты из лога `llama-server` по одному реальному запросу (картинка + вопрос, PQ2_0, Vulkan, RX 7800 XT, контекст 16384):

| Этап | Результат |
|---|---|
| Обработка запроса | 3020 токенов за 7,0 с, около 429 токенов/с |
| Генерация | 73 токена за 1,5 с, около 47 токенов/с |

Это **один запрос, а не бенчмарк**; у вас цифры будут другими. Скорость генерации (токенов в секунду) от уровня рассуждения не зависит: уровень меняет только то, **сколько токенов модель сгенерирует** до ответа. Поэтому на `xhigh` ответ приходит дольше, чем на `medium`, даже при той же скорости. Систематического сравнения `medium` и `xhigh` по времени и точности не делалось.

Юнит-тесты логики (без GUI) выполнялись на Linux (Python 3.10 и 3.13) и у автора на Windows (Python 3.11); в GitHub Actions они запускаются на Python 3.10-3.13 (`.github/workflows/tests.yml`).

**Чего проверено не было:** macOS, Linux как рабочая ОС (библиотека `keyboard` там требует root или не поддерживается), NVIDIA-карты, несколько мониторов, формат `PTQ1_0` и обычный (не PrismML) llama.cpp с форматом `Q2_0`, сборка HIP вместо Vulkan, другие модели в режиме `openai`.

Качество ответов зависит от модели, а не от программы. Цифр «правильных ответов в процентах» здесь нет.

Программа - инструмент для самопроверки, тренировки и работы со своими материалами. Прежде чем применять её к чему-либо оцениваемому (экзамен, зачёт, отбор, сертификация), проверьте правила: во многих таких случаях помощь посторонних инструментов запрещена, а нарушение может привести к дисквалификации или отчислению. Ответственность за использование лежит на вас.

Модель может ошибаться, причём уверенно. Не полагайтесь на её ответ там, где цена ошибки высока, и проверяйте по документации. Если ответ касается кода, самая надёжная проверка - запустить этот код: бывает, что ошибается не модель, а «правильный ответ» в самом тесте.

## Установка

### Общая часть: программа

Нужен Python 3.10 или новее (с `tkinter`: на Windows он входит в стандартный установщик с опцией *tcl/tk and IDLE*).

```powershell
git clone https://github.com/Paoak/screen-helper.git
cd screen-helper
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

Если PowerShell не даёт активировать окружение, выполните один раз `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`.

Дальше выберите вариант A (проще всего) или B (мощнее). Можно настроить оба и переключаться между ними, см. [запуск в один клик](#запуск-в-один-клик-bat).

> **Обе модели одновременно не запускайте.** В 16 ГБ видеопамяти вместе Gemma 12B и Bonsai 27B не поместятся: закройте один сервер, прежде чем стартовать другой.

### Вариант A: Ollama и Gemma

1. Установите Ollama: <https://ollama.com/download>.
2. Скачайте vision-модель:
   ```powershell
   ollama pull gemma4:12b
   ```
3. **Проверьте, что у модели есть `vision`**, иначе картинку она не увидит:
   ```powershell
   ollama show gemma4:12b
   ```
   В блоке `Capabilities` должно быть слово `vision`. Слово `thinking` означает, что модель умеет рассуждать (см. [режим рассуждения](#режим-рассуждения)).
4. Прогрейте модель (первый запуск грузит её в видеопамять и идёт заметно дольше):
   ```powershell
   ollama run gemma4:12b "привет"
   ```
5. Убедитесь, что модель на видеокарте, а не на процессоре:
   ```powershell
   ollama ps
   ```
   В колонке `PROCESSOR` должно быть `100% GPU`. Если там указан CPU, всё будет в разы медленнее: проверьте драйверы видеокарты.
6. Запустите программу (настройки по умолчанию уже рассчитаны на этот вариант):
   ```powershell
   python main.py
   ```
   В консоли появится строка со списком горячих клавиш и `Модель: gemma4:12b | think: True | num_ctx: 16384`.

### Вариант B: llama.cpp и Bonsai 27B

Этот вариант нужен для моделей, которые не запускаются через Ollama. Bonsai в формате `PQ2_0` и `PTQ1_0` требует **форк llama.cpp от PrismML**: обычный llama.cpp эти форматы не откроет (по данным статьи, формат `Q2_0` запускается и на обычном llama.cpp сборки b11556 и новее, но мы его не проверяли). Установку и сервер делает демо-репозиторий PrismML, поэтому ему нужна **отдельная папка**, не внутри `screen-helper`.

#### 1. Установка Bonsai-demo (один раз)

В обычном PowerShell:

```powershell
cd C:\Users\<вы>
git clone https://github.com/PrismML-Eng/Bonsai-demo.git
cd Bonsai-demo
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
$env:BONSAI_OPENWEBUI = "0"
$env:BONSAI_CODE_INTERPRETER = "0"
.\setup.ps1
```

Что делает `setup.ps1` (по выводу у автора, Windows):

- проверяет Python (нашёл 3.11), ставит менеджер пакетов `uv` и создаёт в папке свой `.venv` (он **не связан** с `.venv` проекта Screen Helper);
- пишет `Vulkan SDK detected` (что скрипт делает при его отсутствии, мы не проверяли);
- спрашивает необязательный токен Hugging Face: нажмите **Enter**, он нужен только для обхода лимитов скачивания;
- скачивает веса семейства `bonsai25`, размер 27B: **14,4 ГБ**, 3 файла (две альтернативные сборки модели и проектор для картинок). У автора это заняло около 17 минут при скорости около 5 МБ/с;
- скачивает бинарники llama.cpp от PrismML (у автора `llama-prism-b12178`) в `bin\vulkan`.

Две переменные `BONSAI_*` отключают установку веб-интерфейса Open WebUI и интерпретатора кода: для нашей задачи они не нужны.

В папке `models\bonsai25-gguf\27B` окажутся:

| Файл | Размер | Что это |
|---|---|---|
| `Ternary-Bonsai-2.5-27B-PQ2_0-mtp.gguf` | 7,49 ГБ | Веса. **Именно эту сборку скрипт загрузил по умолчанию** |
| `Ternary-Bonsai-2.5-27B-PTQ1_0-mtp.gguf` | 6,23 ГБ | Более сжатая сборка (в статье её рекомендуют для NVIDIA). Скачана, но сервером не используется |
| `Ternary-Bonsai-2.5-27B-mmproj-Q8_0.gguf` | 0,63 ГБ | Проектор: «глаза» модели. Без него картинки не принимаются |

В суффиксе `-mtp` в названии - вариант с блоком ускорения генерации (multi-token prediction). Судя по логу, сервер в нашей конфигурации этот блок **не использует**: при запуске появляются предупреждения `model has unused tensor blk.64...`, они безвредны.

#### 2. Запуск сервера

```powershell
cd C:\Users\<вы>\Bonsai-demo
$env:BONSAI_CTX = "16384"
.\scripts\start_llama_server.ps1
```

`BONSAI_CTX` - размер контекста в токенах. Скрипт сам подключает проектор, выбирает бинарник под вашу видеокарту (`-ngl 99`, все слои на GPU) и слушает `http://127.0.0.1:8080`. Окно с сервером **оставьте открытым**. Сервер готов, когда в логе появится:

```
srv    load_model: loaded multimodal model, '...mmproj-Q8_0.gguf'
srv  server_on_li: listening on http://127.0.0.1:8080
```

Проверка: откройте <http://localhost:8080> в браузере, там встроенный чат. Прикрепите картинку и задайте вопрос: если модель отвечает, значит, и сервер, и проектор работают.

Что выбрать для контекста:

| `BONSAI_CTX` | Когда |
|---|---|
| `16384` | Достаточно для одного скриншота и рассуждения `medium` |
| `32768` | Рекомендую для `reasoning_effort: "xhigh"`: рассуждение на высоком уровне длинное и может не уместиться в 16K |

Расход памяти на контекст по документации PrismML: кэш 27B в FP16 занимает **64 КиБ на токен**, то есть примерно 2 ГиБ на 32K токенов. Вместе с весами (около 8 ГБ с проектором) на 16 ГБ должно хватать с запасом. Если сервер падает с ошибкой памяти, уменьшите `BONSAI_CTX` или посмотрите [советы по экономии памяти](https://docs.prismml.com/resources/troubleshooting.md) в документации PrismML.

Что видно в логе по скорости (запрос из встроенного чата): `prompt eval ... 428.69 tokens per second`, `eval ... 47.12 tokens per second`. Название видеокарты в этом (неподробном) логе не печатается; что модель работает на GPU, видно по скорости, по `-ngl 99` в заголовке и по занятой видеопамяти в диспетчере задач.

#### 3. Запуск программы с конфигом Bonsai

Откройте **второе** окно терминала в папке проекта:

```powershell
cd C:\Users\<вы>\...\screen-helper
Copy-Item examples\config.bonsai-llamacpp.json config.bonsai.json
.\.venv\Scripts\python.exe main.py --config config.bonsai.json
```

В консоли должна появиться строка:

```
Сервер: http://localhost:8080/v1/chat/completions (llama-server / OpenAI API) | think: True | reasoning_effort: medium
```

Если вместо неё `Модель: gemma4...`, значит, программа прочитала другой конфиг (по умолчанию она берёт `config.json` из текущей папки, если он есть): запускайте с явным `--config`.

### Запуск в один клик (.bat)

Чтобы не вспоминать команды, сделайте по `.bat`-файлу на каждый вариант. Они работают двойным кликом, не требуют активации `.venv` и не зависят от политики PowerShell.

Подготовьте конфиги в корне проекта. Личные конфиги вида `config.*.json` занесены в `.gitignore`, в репозиторий они не попадут:

- `config.gemma.json` - ваши настройки для Ollama (например, копия `config.example.json` с нужной моделью);
- `config.bonsai.json` - копия `examples\config.bonsai-llamacpp.json`.

`start-gemma.bat` (в корне проекта):

```bat
@echo off
cd /d "%~dp0"
.venv\Scripts\python.exe main.py --config config.gemma.json
pause
```

`start-bonsai.bat` (в корне проекта):

```bat
@echo off
cd /d "%~dp0"
.venv\Scripts\python.exe main.py --config config.bonsai.json
pause
```

`start-server.bat` - положите в папку **Bonsai-demo**, а не в проект (в нём прописан размер контекста для сервера):

```bat
@echo off
cd /d "%~dp0"
set BONSAI_CTX=32768
powershell -ExecutionPolicy Bypass -File scripts\start_llama_server.ps1
```

Порядок запуска:

| Нужна модель | Что запускать |
|---|---|
| Gemma (Ollama) | запустить Ollama, затем `start-gemma.bat` |
| Bonsai | `start-server.bat`, дождаться `listening on http://127.0.0.1:8080`, затем `start-bonsai.bat` |

`pause` в конце `.bat` оставляет окно открытым, если программа завершилась с ошибкой, и вы успеваете прочитать текст.

### Запуск из PyCharm

1. Откройте папку как проект, интерпретатором выберите `.venv` проекта.
2. Установите зависимости в **это** окружение (терминал PyCharm, `Alt+F12`): `pip install -r requirements.txt`.
3. Запустите `main.py` кнопкой Run. Для другого конфига добавьте в *Run → Edit Configurations → Parameters*: `--config config.bonsai.json`. Остановить можно красным квадратом или хоткеем **Ctrl+Alt+Q**.

> Хоткей **Ctrl+Alt+S** глобальный и срабатывает в том числе в PyCharm, где он открывает настройки. Если мешает, поменяйте его в конфиге (см. [Настройка](#настройка)).

## Использование

| Хоткей | Действие |
|---|---|
| **Ctrl+Alt+S** | снимок всего основного экрана |
| **Ctrl+Alt+A** | снимок выделенной области: тянете рамку левой кнопкой мыши; **Esc** или правая кнопка - отмена |
| **Ctrl+Alt+H** | скрыть / показать окно с ответом |
| **Ctrl+Alt+Q** | выйти из программы |

Рекомендации:

- **Используйте выделение области (Ctrl+Alt+A).** Чем меньше лишнего на картинке и крупнее текст, тем точнее модель читает вопрос, и тем быстрее ответ.
- Захватывайте **вопрос вместе со всеми вариантами ответа**. Если вариант не попал в кадр, модель его не видит.
- Не отправляйте следующий снимок, пока не получили ответ: предыдущий запрос будет отменён, и его ответ вы не увидите.
- Первый запрос после запуска или после долгого простоя медленнее остальных: модель загружается в память (в Ollama её там держит `keep_alive`).
- Если зажать хоткей или нажать несколько раз подряд, в консоли будут строки `capture: нажатие пропущено`. Это защита от дублей, а не ошибка.

## Настройка

Все настройки необязательны. Чтобы что-то изменить, скопируйте пример и оставьте в нём только нужные поля:

```powershell
Copy-Item config.example.json config.json
```

Программа читает `config.json` из **текущей папки** при запуске. Другой файл можно указать явно (так удобно держать несколько конфигов, см. [.bat](#запуск-в-один-клик-bat)):

```powershell
python main.py --config config.bonsai.json
```

В `.gitignore` занесены `config.json` и `config.*.json` в корне проекта, чтобы ваши личные промпты и настройки случайно не попали в репозиторий (`config.example.json` и папка `examples/` остаются в нём). Поля, имена которых начинаются с `_` (например `_comment`), игнорируются, так что в JSON можно оставлять пометки.

| Поле | По умолчанию | Для какого бэкенда | Описание |
|---|---|---|---|
| `backend` | `"ollama"` | оба | `"ollama"` или `"openai"` (llama-server и другие OpenAI-совместимые серверы) |
| `ollama_url` | `http://localhost:11434/api/chat` | ollama | Адрес Ollama. Другой порт или другая машина: меняйте здесь (см. [приватность](#приватность-и-безопасность)) |
| `openai_url` | `http://localhost:8080/v1/chat/completions` | openai | Адрес сервера. **Должен заканчиваться на `/v1/chat/completions`** |
| `model` | `gemma4:12b` | оба | Ollama: имя модели из `ollama list` (нужен `vision`). llama-server с одной загруженной моделью имя не проверяет, подойдёт любое, например `bonsai-27b` |
| `keep_alive` | `"30m"` | ollama | Сколько держать модель в памяти после запроса |
| `num_ctx` | `16384` | ollama | Размер контекста. Для одного скриншота без рассуждения хватает 8192; **с рассуждением не меньше 16384**. У llama-server контекст задаётся при запуске сервера (`BONSAI_CTX` / `-c`), это поле игнорируется |
| `max_side` | `1600` | оба | Максимальная сторона скриншота в пикселях. Меньше: быстрее, но мелкий текст читается хуже |
| `think` | `true` | оба | `true`, `false` или уровень `"low"`, `"medium"`, `"high"` ([подробнее](#режим-рассуждения)) |
| `reasoning_effort` | `null` | openai | Уровень рассуждения, например `"medium"` или `"xhigh"`. `null` - не передавать, решает модель |
| `max_tokens` | `null` | оба | Потолок длины ответа **вместе с рассуждением**. `null` - не ограничивать. При высоком рассуждении ставьте 8192-16384 |
| `temperature`, `top_p`, `top_k`, `min_p` | `null` | оба | Параметры сэмплинга. `null` - не передавать, решает сервер. Значение `0` допустимо и отправляется как есть |
| `extra_body` | `{}` | оба | Любые дополнительные поля тела запроса, добавляются как есть (вложенные объекты сливаются). Запасной выход, если сервер ждёт параметр иначе |
| `request_timeout` | `300` | оба | Сколько секунд ждать очередную порцию данных. Для `xhigh` на сложных вопросах ставьте 600-900 |
| `hotkey_full` | `ctrl+alt+s` | оба | Хоткей снимка экрана |
| `hotkey_area` | `ctrl+alt+a` | оба | Хоткей снимка области |
| `hotkey_hide` | `ctrl+alt+h` | оба | Хоткей скрытия окна ответа |
| `hotkey_quit` | `ctrl+alt+q` | оба | Хоткей выхода |
| `prompt` | см. `config.py` | оба | Инструкция для модели ([как писать](#как-писать-и-менять-промпт)) |

Хоткеи задаются в формате библиотеки [`keyboard`](https://github.com/boppreh/keyboard), например `ctrl+shift+f9`.

Ошибки в файле (неверный JSON, неизвестное поле, неподходящий тип значения, `backend` не из списка, температура меньше нуля, `top_p` вне 0-1) программа сообщает понятным текстом и завершается с кодом 2, не запуская GUI.

  "model": "bonsai-27b",
  "think": true,

Параметры сэмплинга `temperature=1.0, top_p=0.95, top_k=20, min_p=0` - рекомендация из статьи для режима рассуждения. У предыдущего поколения (Ternary Bonsai 27B) в карточке модели указаны другие: `temperature=0.7, top_p=0.95, top_k=20`. ## Как писать и менять промпт

Промпт - это текст, который отправляется модели вместе со скриншотом. Он сильнее всего влияет на формат и качество ответа. Хорошо работает такая структура:

1. **Что на картинке:** «На скриншоте вопрос с вариантами ответа».
2. **Тематика** (если она известна заранее): «Вопросы про API: пагинация, фильтрация, асинхронные операции». Это помогает модели выбрать правильную терминологию и отсечь неподходящие толкования.
3. **Формат ответа:** «Сначала одной строкой правильный вариант (буква и текст), затем 1-2 предложения объяснения».
4. **Поведение при неуверенности:** «Если текст нечитаем или вопрос обрезан - так и скажи, ничего не выдумывай». Без этой фразы модель склонна уверенно додумывать то, чего не видит.
5. **Язык:** «Отвечай на языке вопроса».

Практические советы:

- **Не просите «только букву», если хотите проверять ответ.** Короткое объяснение позволяет заметить, что модель поняла вопрос неправильно. Для простых вопросов «только вариант» допустимо и быстрее (см. `examples/config.fast.json`).
- Режим рассуждения повышает точность за счёт самого рассуждения, а не за счёт «подробных объяснений» в ответе. Просить объяснять шаг за шагом при включённом рассуждении обычно незачем.
- Для вопросов с несколькими правильными ответами укажите это явно: «Если правильных вариантов несколько, перечисли все».
- Для открытых вопросов уточняйте длину: «ответ в 2-3 предложениях».
- Меняйте промпт в конфиге, а не в коде, и проверяйте на нескольких разных вопросах, а не на одном.
- Слишком длинный промпт с множеством правил может ухудшить результат у небольших моделей. Начинайте с короткого.

Пример промпта для узкой темы лежит в `examples/config.api-questions.json`.

## Режим рассуждения

Часть современных моделей умеет **рассуждать перед ответом**: сначала генерирует цепочку рассуждений, и только потом итоговый ответ. Рассуждение приходит отдельным полем потока (Ollama: `message.thinking`; llama-server: `reasoning_content`), а ответ - отдельно. Программа **не показывает** рассуждение, только счётчик символов, пока оно идёт.

**Когда включать:** вопросы с логикой, расчётами, подвохами, несколькими «похожими» вариантами, вопросы по сложной терминологии. Точность обычно заметно выше.

**Когда выключать:** простые фактические вопросы, когда важна скорость. С рассуждением ответ может идти от десятков секунд до нескольких минут (зависит от модели, видеокарты и вопроса), без него - обычно за несколько секунд.

**Цена рассуждения:**

- *Время.* Рассуждение - это тоже сгенерированные токены.
- *Контекст.* Рассуждение занимает место в контексте (Ollama: `num_ctx`, llama-server: `BONSAI_CTX` / `-c`). Если места не хватает, модель может так и не дойти до ответа. Программа в этом случае покажет сообщение «Модель закончила, но не вернула ответ…» с советами.
- *Потолок `max_tokens`.* Если задан и слишком мал, генерация оборвётся посреди рассуждения.
- *Память.* Больший контекст увеличивает расход видеопамяти.

### Ollama: параметр `think`

Включение: `"think": true` в конфиге. Программа **всегда отправляет параметр `think` явно**, поэтому значение по умолчанию, зашитое в самой модели, не влияет на её поведение здесь. После изменения контекста проверяйте `ollama ps`: модель должна остаться на `100% GPU`.

**Модели, у которых режима рассуждения может не быть.** Не все модели поддерживают `think`. Проверить можно в `ollama show <модель>`: в `Capabilities` должно быть `thinking`. Если `think` включён, а модель его не поддерживает, Ollama отвечает ошибкой HTTP 400. Программа показывает уведомление «Эта модель не поддерживает режим рассуждения - отвечаю без него…» и **автоматически повторяет запрос без `think`**. Ответ вы получите, но каждый запрос будет начинаться с неудачной попытки, поэтому для таких моделей лучше сразу поставить `"think": false`.

Другие нюансы, зависящие от модели (смотрите карточку модели на [ollama.com/library](https://ollama.com/library) и документацию Ollama):

- Некоторые модели принимают вместо `true`/`false` **уровень** (`"low"`, `"medium"`, `"high"`). Программа пропускает такие значения как есть.
- У некоторых моделей рассуждение нельзя отключить полностью, а у некоторых бывают отдельные «thinking»- и «instruct»-сборки с разными тегами.
- Для рассуждающих моделей Ollama должна быть достаточно свежей: на старых версиях параметра `think` может не быть, и запрос завершится ошибкой.

### llama-server: `reasoning_effort`

Для Bonsai 27B уровень рассуждения задаётся полем `reasoning_effort`. По документации PrismML, **по умолчанию у модели высокий уровень (`xhigh`)**, а `"medium"` даёт более короткие рассуждения и ответы. Уровень `"low"`, по их же разделу troubleshooting, у 27B не поддерживается и рассуждение не сокращает.

Как программа его передаёт (при `backend: "openai"`):

| Что в конфиге | Что уходит на сервер |
|---|---|
| `reasoning_effort: "medium"` | поле `reasoning_effort: "medium"` **и** `chat_template_kwargs: {"reasoning_effort": "medium"}` |
| `reasoning_effort: null`, `think: "high"` | то же, но со значением из `think` |
| оба заданы | побеждает `reasoning_effort` |
| `think: false` | `chat_template_kwargs: {"enable_thinking": false}` и `thinking_budget_tokens: 0` (уровень игнорируется) |
| `think: true`, `reasoning_effort: null` | ничего: действует значение сервера и модели |

Сразу два способа передачи - сознательный выбор: документация PrismML в разных местах описывает, куда класть этот параметр, по-разному, а неизвестные поля сервер игнорирует. **Мы не проверяли, влияет ли `think: false` на Bonsai так, как задумано**: надёжнее всего отключать рассуждение на стороне сервера флагом `--reasoning-budget 0` (по документации PrismML). Если какой-то параметр ушёл не туда, поправьте его через `extra_body` без изменения кода.

Как выбирать уровень:

| Уровень | Ответ | Когда |
|---|---|---|
| `"medium"` | короче, быстрее | первый вариант для большинства вопросов; контекст 16384 |
| `"xhigh"` | дольше, подробнее | сложные вопросы с подвохами, когда `medium` ошибается; контекст 32768, `max_tokens` 16384, `request_timeout` 900 |

Выбирайте не «на глаз»: возьмите 5-10 вопросов, на которых модель ошибалась, и прогоните на обоих уровнях, замечая время и число верных ответов. Прежде чем переходить на `xhigh`, убедитесь, что ошибка именно в рассуждении, а не в чтении текста (см. следующий раздел).

## Точность чтения текста со скриншота

Модель ошибается не только «в мыслях», но и **при чтении картинки**: путает буквы вариантов, пропускает слово, склеивает строки, неверно читает код. Рассуждение (`xhigh`) в этом случае не поможет: оно улучшает ход мысли, а не зрение. Сначала разберитесь, какой это случай. Проще всего отправить тот же скриншот во встроенный чат сервера (<http://localhost:8080>) и посмотреть, что модель «видит»: попросите её просто переписать текст с картинки.

Что помогает, по убыванию эффективности:

1. **Выделяйте область**, а не весь экран. Крупнее текст на картинке - точнее чтение.
2. **Увеличьте масштаб страницы** в браузере (Ctrl+колесо), прежде чем снимать.
3. **Поднимите `max_side`** (например, до 2000-2400), если мелкий текст теряется при уменьшении. Цена: больше токенов на картинку и дольше обработка.
4. **Для Bonsai: флаг сервера `--image-min-tokens 1024`.** При запуске сервера в логе есть предупреждение:

   ```
   W load_hparams: Qwen-VL models require at minimum 1024 image tokens to function correctly on grounding tasks
   W load_hparams: if you encounter problems with accuracy, try adding --image-min-tokens 1024
   W load_hparams: more info: https://github.com/ggml-org/llama.cpp/issues/16842
   ```

   Смысл: проектор модели принадлежит семейству Qwen-VL, которому для точной работы с текстом и расположением элементов нужно **не меньше 1024 токенов на изображение**. Без этого флага небольшой выделенный фрагмент кодируется малым числом токенов, и мелкий текст может читаться хуже. Если у вас «путаный» текст (модель путает слова, цифры, варианты ответов), добавьте флаг при запуске сервера. Мы **проверяли только то, что предупреждение появляется**, а не его влияние на точность: оцените эффект сами на ваших скриншотах.

   Как передать флаг: по документации PrismML, скрипт запуска передаёт дополнительные аргументы в `llama-server`, например для Linux/macOS `./scripts/start_llama_server.sh -c 32768`. Для Windows это выглядит так:

   ```powershell
   .\scripts\start_llama_server.ps1 --image-min-tokens 1024
   ```

   (для `.ps1`-варианта мы эту передачу отдельно не проверяли; если сервер не принял флаг, посмотрите текст скрипта `scripts\start_llama_server.ps1`). В `start-server.bat` добавьте его в конец строки с `powershell`.

   Цена: каждое изображение занимает минимум 1024 токена контекста, то есть обработка небольших фрагментов станет дольше (у автора 3020 токенов запроса обрабатывались около 7 секунд), а контекста на рассуждение останется чуть меньше.
5. **Явно скажите в промпте** («Прочитай вопрос и все варианты», «если текст нечитаем - скажи») - так модель реже додумывает то, чего не видит.
6. **Проверяйте спорные ответы**: запускайте код, сверяйтесь с документацией. Модель, ключ теста и «ответ из интернета» могут ошибаться, причём каждый по-своему.

## Выбор модели

Подходит любая vision-модель: из Ollama (с capability `vision`) или любая, которую умеет отдавать OpenAI-совместимый сервер вместе с проектором. Ниже не рейтинг, а отправные точки для сравнения на ваших вопросах: списки моделей быстро меняются, актуальные смотрите на [ollama.com/library](https://ollama.com/library).

| Модель | Бэкенд | Комментарий |
|---|---|---|
| `gemma4:12b` | ollama | Проверенная конфигурация для простого старта: на 16 ГБ целиком в видеопамяти, vision и thinking |
| Ternary Bonsai 2.5 27B (PQ2_0) | openai | Проверенная: 7,49 ГБ весов + 0,63 ГБ проектора, около 47 токенов/с на RX 7800 XT. Крупнее Gemma, при этом помещается в 16 ГБ с запасом под контекст. Требует форк llama.cpp от PrismML |
| `qwen3-vl:8b` | ollama | Компактная (порядка 6 ГБ), сильна в распознавании текста на скриншотах; стоит сравнить, особенно если вопросы не на английском. Не проверялась |
| `qwen3-vl:30b` | ollama | MoE-модель: на 16 ГБ часть слоёв уйдёт в оперативную память, зато активна лишь малая часть параметров. Скорость нужно мерить самому. Не проверялась |
| Плотные модели крупнее 20-30B в обычной квантизации | любой | На 16 ГБ видеопамяти уходят в RAM и работают медленно; для сценария «нажал клавишу, получил ответ» обычно неудобны |

Как выбирать:

1. Смотрите, чтобы **модель + проектор + контекст помещались в видеопамять**. Грубая оценка для квантизации Q4: 0.55-0.65 ГБ на миллиард параметров, плюс vision-проектор и KV-кэш, который растёт вместе с контекстом (у Bonsai 27B по документации 64 КиБ на токен).
2. Проверяйте загрузку: Ollama - `ollama ps` (`100% GPU` - хорошо); llama-server - видеопамять в диспетчере задач и скорость в логе. Если часть работы ушла на процессор, скорость резко упадёт.
3. Сравнивайте модели **на одних и тех же скриншотах**: смените конфиг и отправьте тот же вопрос. Это надёжнее любого обзора.
4. Если ответ плохой на мелком тексте, сначала попробуйте выделить область, поднять `max_side` и (для Bonsai) `--image-min-tokens 1024`, а не менять модель.

## Краевые случаи и устранение неполадок

### Общие

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| Хоткеи ничего не делают, в консоли нет строки `hotkey: …` | Библиотека `keyboard` не получает нажатия | Запустите программу (или PyCharm) **от имени администратора**. Проверьте, не занята ли комбинация другой программой (скриншотеры, мессенджеры иногда используют Ctrl+Alt+A). Смените хоткей в конфиге |
| Строка `hotkey: …` есть, а окна нет | Ошибка при захвате или запросе | Смотрите консоль: после `hotkey:` должны идти `capture:` и `request #N:`, на каком шаге оборвалось - там и причина. Если есть трассировка - пришлите её в Issue |
| Хоткей срабатывает не только у программы (например, открывает настройки PyCharm) | Хоткей глобальный | Смените комбинацию в конфиге |
| Экран затемнён, курсор-«крестик» | Открыт слой выбора области | **Esc** или правая кнопка мыши. Если не помогло: **Ctrl+Alt+Q** или завершите `python.exe` в диспетчере задач |
| Две копии программы, всё ведёт себя странно | Две копии одновременно ловят хоткеи | Закройте лишнюю (в PyCharm: красный квадрат у старого запуска, либо диспетчер задач) |
| Запустил, а в консоли `Модель: gemma4…`, хотя ждал Bonsai | Прочитан другой конфиг: по умолчанию берётся `config.json` из текущей папки | Запускайте с явным `--config config.bonsai.json` или через `start-bonsai.bat` |
| «Думаю…» очень долго | Включено рассуждение; модель только загружается; модель не на GPU | Смотрите счётчик символов: растёт - модель работает. Проверьте загрузку GPU. Для простых вопросов выключите рассуждение или поставьте `medium` |
| «Модель закончила, но не вернула ответ» | Рассуждение исчерпало контекст или `max_tokens` | Увеличьте контекст (Ollama: `num_ctx`; llama-server: `BONSAI_CTX`), `max_tokens`, либо снизьте `reasoning_effort` до `"medium"` / выключите `think` |
| Ответ не относится к скриншоту / игнорирует картинку | У модели нет `vision` (Ollama) или сервер без проектора | `ollama show <модель>`: нужен `vision`; для llama-server запускайте с `--mmproj` (скрипты PrismML делают это сами) |
| Модель путает буквы вариантов, не видит часть текста | Мелкий текст, сильное сжатие, вопрос обрезан | Раздел [«Точность чтения текста»](#точность-чтения-текста-со-скриншота) |
| Вопрос не помещается на экране (нужна прокрутка) | Снимок захватывает только видимое | Уменьшите масштаб страницы, чтобы всё влезло. Раздельные снимки не помогут: запросы независимы, и модель не видит предыдущий |
| Снимок чёрный | Защищённое содержимое (DRM), аппаратное ускорение некоторых окон | Отключите аппаратное ускорение в приложении/браузере, если это возможно |
| Тест на втором мониторе | Снимается только основной монитор | Перетащите окно с вопросом на основной монитор |
| Рамка выделения смещена, снимок «не в том месте» | Нестандартный масштаб Windows (125/150%), несколько мониторов с разным DPI | Программа включает DPI-режим сама; если смещение есть, опишите в Issue конфигурацию мониторов |
| Ответ на другом языке | Промпт не указывает язык | Добавьте «Отвечай на языке вопроса» (или конкретный язык) |
| Ответ уверенный, но неверный | Любая модель ошибается; особенно по узким темам и версиям библиотек/API | Включите рассуждение, выделите область, сравните с другой моделью, проверьте по документации или запуском кода |
| Антивирус ругается на программу | Глобальный перехват клавиш выглядит подозрительно для эвристик | Код открыт (см. [приватность](#приватность-и-безопасность)); при необходимости добавьте папку в исключения |
| `Ошибка настроек: …` при запуске | Неверный конфиг | Текст ошибки указывает поле; сверьтесь с таблицей настроек. Файл с BOM (из Блокнота) принимается |

### Только для Ollama

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| «Не удаётся подключиться к Ollama» | Ollama не запущена или другой адрес/порт | Запустите Ollama, проверьте `ollama list`, при необходимости поправьте `ollama_url` |
| «Модель … не найдена» | Модель не скачана или имя не совпадает | `ollama pull <имя>`; сверьте `model` с `ollama list` |
| «Не хватает памяти…» или всё очень медленно | Модель или контекст не помещаются в память | Уменьшите `num_ctx`, выберите модель поменьше, закройте другие программы на GPU; смотрите `ollama ps` |
| «Ollama не отвечает больше N с» | Таймаут | Увеличьте `request_timeout`; для рассуждающих моделей на сложных вопросах это нормально |
| Первый запрос после простоя долгий | Модель выгружена из памяти | Увеличьте `keep_alive`, например `"2h"` |

### Только для llama-server (Bonsai)

| Симптом | Вероятная причина | Что делать |
|---|---|---|
| «Не удаётся подключиться к серверу (…). Запущен ли llama-server?» | Сервер не запущен, ещё не загрузился или порт/адрес другой | Запустите `start-server.bat`, дождитесь `listening on http://127.0.0.1:8080`, сверьте `openai_url` |
| «Сервер ещё загружает модель» | Модель ещё читается с диска в память (ответ HTTP 503) | Подождите и повторите |
| «Сервер запущен без модуля зрения…» (в тексте ошибки `--mmproj`) | Сервер запущен без проектора, поэтому картинки не принимает | Запускайте скриптом PrismML (он подключает проектор сам) или добавьте `--mmproj <файл mmproj>` |
| «Скриншот и рассуждение не поместились в контекст сервера» | Контекст сервера слишком мал | Перезапустите сервер с большим `BONSAI_CTX` (16384 → 32768) или уменьшите `max_side` |
| «Сервер ответил 404 по адресу …» | В `openai_url` не тот путь | Адрес должен заканчиваться на `/v1/chat/completions` |
| «Не хватает памяти: …» | Контекст или модель не помещаются в видеопамять | Меньший `BONSAI_CTX`; для карты на 12 ГБ статья советует начинать с 8K-16K |
| Сервер не стартует: порт 8080 занят | Другая программа слушает 8080 (или старый сервер ещё жив) | Закройте старый сервер (в его окне `Ctrl+C`) или освободите порт; если порт сменили, поправьте `openai_url` |
| `setup.ps1` не запускается: «выполнение сценариев отключено» | Политика выполнения PowerShell | В этом же окне: `Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass` |
| В окне ответа вместо ответа виден сырой текст рассуждения или тег `<think>` | Сервер отдаёт рассуждение не в отдельном поле, а внутри ответа | Программа ждёт рассуждение в поле `reasoning_content` (так делает llama-server по умолчанию). У автора такого не наблюдалось; если встретите, не меняйте у сервера формат вывода рассуждения (`--reasoning-format`) и приложите вывод консоли к Issue |
| Параметр `reasoning_effort` ни на что не влияет | Сервер или шаблон модели принимает его иначе | Попробуйте передать нужное поле через `extra_body` (см. [таблицу настроек](#настройка)) и проверьте в логе сервера, что запрос дошёл |
| В логе много `unused tensor blk.64...` | Блок ускорения MTP не используется | Игнорируйте: это безвредное предупреждение |

## Приватность и безопасность

- **Всё локально.** По умолчанию снимок уходит только на `localhost`: `11434` (Ollama) или `8080` (llama-server). Если вы укажете в `ollama_url` / `openai_url` другую машину, снимки экрана будут отправляться на неё. Делайте это осознанно.
- **Сервер llama.cpp не защищён паролем.** В логе запуска есть предупреждение `no API key is set and CORS allows all origins`. Скрипты PrismML слушают только `127.0.0.1` (снаружи сервер недоступен), но любая программа на этом компьютере может отправлять ему запросы. **Не меняйте `BONSAI_HOST` на `0.0.0.0`**: так сервер станет доступен всей сети без пароля. Отправку ключа API программа сейчас не поддерживает.
- **Снимки не сохраняются на диск.** Они живут в памяти, кодируются в JPEG и передаются в запросе.
- **Хоткеи.** Библиотека `keyboard` ставит глобальный перехватчик клавиатуры; для этого она и нужна. Код только регистрирует четыре комбинации через `add_hotkey` и **не записывает и не логирует нажатия**, в консоль печатается лишь строка `hotkey: экран/область`. Убедиться можно, прочитав `screen_helper/app.py`: он короткий.
- **Экран может содержать чужое:** почту, мессенджеры, пароли. Используйте выделение области, чтобы в кадр попадало только нужное.
- **Скрипты стороннего репозитория.** `setup.ps1` из Bonsai-demo скачивает бинарники и модель из интернета и запускает их: перед запуском так же, как с любой чужой программой, просмотрите скрипты и репозиторий.
- Не запускайте программу от администратора без необходимости, и только из источника, которому доверяете.

## Разработка и тесты

Структура проекта:

```
screen-helper/
├── main.py                    # точка входа для PyCharm / python main.py
├── screen_helper/
│   ├── config.py              # настройки, загрузка и проверка конфига
│   ├── core.py                # логика без GUI: запросы к Ollama и llama-server, разбор потоков, состояние окна, защита хоткеев
│   ├── ui.py                  # tkinter: окно ответа и выбор области
│   ├── app.py                 # хоткеи, очередь событий, захват экрана
│   └── __main__.py            # python -m screen_helper
├── tests/                     # pytest
├── examples/                  # примеры конфигов
├── config.example.json        # все настройки с значениями по умолчанию
└── requirements*.txt
```

Логика намеренно отделена от GUI: всё, что можно проверить без экрана и без сервера модели, находится в `config.py` и `core.py`.

Запуск тестов:

```powershell
pip install -r requirements-dev.txt
python -m pytest
```

(`pytest` входит в `requirements-dev.txt`, а не в `requirements.txt`: без него будет ошибка `No module named pytest`.)

**Что покрыто тестами** (на момент публикации - 149 тестов): загрузка и проверка настроек (BOM, неизвестные поля, неверные типы и диапазоны, актуальность файлов-примеров); подготовка картинки (уменьшение без растягивания, разные цветовые режимы, оригинал не меняется); сборка запросов для обоих бэкендов (в том числе `reasoning_effort`, `think: false`, нулевые значения сэмплинга, `extra_body`); разбор потока Ollama и SSE-потока llama-server (рассуждение, ответ, мусорные строки, `[DONE]`, ошибки в потоке); `ask_model` с подменённым сетевым вызовом (успех, отмена устаревшего запроса, 404 модели, нехватка памяти, обрыв соединения, таймаут, автоматический повтор без `think` у Ollama и его отсутствие у llama-server); понятные сообщения об ошибках llama-server (нет проектора, мало контекста, загрузка модели, 404 адреса); перевод выделения мышкой в рамку (DPI-масштаб, выход за края экрана, случайные клики); состояние окна ответа (устаревшие события, ошибка посреди ответа, пустой ответ); защита от дублей хоткея.

**Что тестами не покрыто:** `ui.py` и `app.py` (tkinter, глобальные хоткеи, реальный захват экрана, окно без фокуса). Для них нужен рабочий стол Windows, поэтому они проверяются вручную. Связка `App` с серверами проверялась отдельно на виртуальном экране с поддельными серверами Ollama и llama-server, но в репозиторий этот прогон не входит. Реальные ответы моделей тоже не тестируются: тесты не вызывают ни Ollama, ни llama-server.

## Ограничения и идеи

Известные ограничения: проверено только на Windows; снимается только основной монитор; нет истории запросов; нет отправки ключа API на защищённый сервер; позицию и размер окна ответа можно поменять только в коде (`Overlay` в `ui.py`); параметры `reasoning_effort` и отключение рассуждения для Bonsai реализованы по документации PrismML и проверялись только на поддельном сервере.

Идеи для развития:

- переключение между моделями «на лету» из списка Ollama для сравнения (не реализовано);
- хоткей «спросить ещё раз другой моделью» для того же скриншота;
- хоткей, который переключает рассуждение (`medium` / `xhigh`) без перезапуска;
- снимок всех мониторов (`ImageGrab.grab(all_screens=True)` в Pillow на Windows);
- копирование ответа в буфер обмена;
- перетаскиваемое и изменяемое по размеру окно ответа;
- режим отладки: сохранять отправленную модели картинку и полный ответ, чтобы сравнивать с веб-чатом.
